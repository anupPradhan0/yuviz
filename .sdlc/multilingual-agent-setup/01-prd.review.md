# Review: 01-prd.md (multilingual-agent-setup)
VERDICT: AMBER

1. [minor] Criteria 4-7 and 30 do not say what the server does with a save that omits `mode` (existing API/script callers) or a partial update that leaves an over-cap legacy language list (3+) untouched, so "runs unchanged until edited" can be read as rejecting every unrelated edit to a legacy agent — criteria 4-7, 30 — fix: add a criterion that an absent mode is derived from the language count as in the legacy assumption, and that the cap is enforced only when `supported_languages` or `mode` is in the request.
2. [minor] The PRD refers to "the server-side model registry" as if it exists, but `libs/config_sdk/languages.py` only has per-engine language functions (`tts_languages`, `resolve_languages`) and the services have no download code or list of downloadable models, so the allowlist that criterion 13 gates on is new work nobody has scoped — Scope bullet 3, criterion 13, Constraints — fix: state that a server-side list of downloadable free (engine, model) entries is new, and that it lives next to or is derived from `languages.py`.
3. [minor] Switching from Multilingual with 2 languages to Monolingual is not specified (which language stays, and what happens to the second language's `tts_config_by_language`/`greeting_by_language` entries) — criteria 2, 17, 19 — fix: add a criterion that the mode switch keeps the first (primary) language, drops the other language's per-language entries with a visible notice, and clears models per criterion 19.
4. [minor] Criteria 25-26 do not cover a Multilingual caller who asks in a third language that is not configured, so the reply language there cannot be tested — criteria 25-26 — fix: state that a question in a language outside the two configured ones gets its reply in the agent's primary configured language.
