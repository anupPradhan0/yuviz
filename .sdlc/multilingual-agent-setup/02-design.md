# Design: Monolingual / multilingual agent setup with language-aware free models and RAG replies

## Approach
Add one nullable column, `agents.language_mode`. A NULL mode means "legacy" and keeps today's validation path, so old rows keep working without changes. When the mode is set, `_validate_languages` (`services/config/agents.py`) checks the cap, the mode and model-language support. Monolingual stores exactly today's single-language shape (`language=L`, `supported_languages=NULL`), so the runtime needs no new switching logic and criterion 28 already holds. Multilingual stores today's multilingual shape with exactly 2 entries. Free-model capability and download state come from one server-side registry (`libs/config_sdk/local_models.py`, built on `languages.py`). The Config service serves that registry flat at `/local-models` and owns downloads. Open question 1 is answered as **Config owns it**: the UI only talks REST to Config, and the auth conventions live there. To make that true per host, Config mounts the conversation service's `hf-cache` volume and reaches Ollama over `OLLAMA_BASE_URL`. That is less work than adding an HTTP surface and auth to the gRPC-only Conversation service. The RAG language rule goes in the system prompt (history[0], rebuilt every turn) plus an `answer_in` field on the `search_knowledge` payload. That rule therefore covers any retrieved context.

`_validate_languages` mode branch:
- Mode resolution: `language_mode` in the request wins. Otherwise, when `supported_languages` is in `requested`, mode is derived from the merged language count (1 → `monolingual`, 2+ → `multilingual`) and stored. Otherwise the stored mode is used. A resolved NULL (legacy row, no language fields or mode in the request) takes today's path byte-for-byte.
- The row has a stored mode and the write sets `language_mode: null` → 400 "language_mode can't be cleared".
- `langs` = normalised, de-duplicated `[language, *supported_languages]` (multilingual), or `supported_languages or [language]` (monolingual). A request that sets `monolingual` without `supported_languages` uses `[language]`: switching Multi→Mono keeps the primary language. Every entry must be in `LANGUAGES`.
- Count rules run only when `supported_languages` or `language_mode` is in `requested`, so legacy 3+ rows and revalidation still accept unrelated edits. Multilingual: `len(langs) > 2` → 400 "a multilingual agent can have at most 2 languages"; `len(langs) < 2` → 400 "a multilingual agent needs a second language". Monolingual: `len(langs) != 1` → 400 "a monolingual agent needs exactly 1 language".
- Output: multilingual keeps the existing multilingual columns. Monolingual is `language=L`, `supported_languages=None`, `tts_config_by_language=None`, `greeting_by_language=None`: the dropped language's voice override and greeting are cleared, never kept silently.
- STT (merged `stt_config_id` or tenant default, as today): each `lang not in stt_languages(engine, model)` → 400 "<name> (<engine> <model>) can't recognise <Language> (<code>)". The existing Deepgram `multi` check stays for multilingual.
- TTS: the existing base/override loop runs over `langs` **without** the `lang == "en"` skip. Monolingual checks only the base TTS.

`ModelDownloads` decisions:
- Status per entry. A running job reads `downloading`. Otherwise the on-disk check runs: faster_whisper uses `faster_whisper.utils.download_model(name, local_files_only=True)`, the same path the runtime loads with. Kokoro uses `huggingface_hub.hf_hub_download("hexgrad/Kokoro-82M", f, local_files_only=True)` for `config.json`, `kokoro-v1_0.pth` and `voices/{name}.pt`. Ollama uses one `GET {OLLAMA_BASE_URL}/api/tags` per status call. That status describes only the host Ollama: an Ollama provider config with an explicit `extra.base_url` different from `OLLAMA_BASE_URL` is treated as externally managed, so the editor shows no ready/not-ready badge and does not call `trigger` for it. Config never pulls into a URL taken from a provider config (no SSRF surface). macOS reads `shutil.which("say")`. A found model reads `ready`. Otherwise a failed job reads `failed` with an error string, a missing model reads `missing`, and macOS without `say` reads `unavailable`. Disk checks run via `asyncio.to_thread`.
- `trigger`: not in `LOCAL_MODELS`, or engine `macos` → `LookupError` (400). Already running → no new job. Then the awaited on-disk check; ready → no job. After that await, re-check in one synchronous block with no `await` inside: already running (a concurrent trigger won) → return `"downloading"`, no new job; running jobs ≥ `_MAX_CONCURRENT_DOWNLOADS = 2` → `DownloadCapReached` (429); otherwise insert the job, then spawn. The final check-and-insert is atomic on the event loop, so two concurrent triggers of one model spawn once and two distinct triggers cannot both pass a full cap (lesson 8, in-process).
- HF downloads: `asyncio.create_subprocess_exec(sys.executable, "-m", "services.config.model_downloads", engine, name)`. argv comes only from the registry entry, never from the request string. Ollama: a streaming `POST /api/pull` in an `asyncio.Task`. `aclose()` terminates the subprocesses (kill after 5 s) and cancels the tasks.
- The job error stored and returned is `"download failed (<ExceptionClass>)"` or `"exit <code>"`. It holds no paths, tenant, agent or user data (criterion 31).

## Data
```sql
-- Monolingual | multilingual; NULL = agent saved before modes existed (legacy validation path).
ALTER TABLE agents ADD COLUMN IF NOT EXISTS language_mode TEXT
    CHECK (language_mode IN ('monolingual', 'multilingual'));
```
Placed beside `supported_languages` (`database/schema.sql:140`). The column is added without a backfill, so lessons 5, 10 and 13 do not apply: every existing row is NULL and passes the CHECK. The cap is not a DB constraint: legacy 3+ rows must keep running, and the server enforces it on every moded write.

## Interfaces

- `libs/config_sdk/local_models.py`: `@dataclass(frozen=True) class LocalModel: engine: str; role: str; name: str; label: str; languages: frozenset[str] | None`; `LOCAL_MODELS: tuple[LocalModel, ...]`; `def find_local_model(engine: str, name: str) -> LocalModel | None`

- `GET /local-models`: `Depends(get_current_user)`. Returns `[{engine, role, name, label, languages: [str] | null, status: "ready"|"missing"|"downloading"|"failed"|"unavailable", error: str | null}]`, the same for every caller.
- `POST /local-models/downloads`, body `{engine, name}`: `Depends(require_role("superadmin", "admin"))`, matching agent writes in `services/config/routers/agents.py:127`. Returns 202 `{status:"downloading"}`, 200 `{status:"ready"}`, 400 not in the registry, 429 at the cap. It never touches the DB, so it needs no `tenant_conn`/tenant binding.
- `services/config/provider_configs.py`: `async def list_provider_voices(provider_id: Any, *, secret_resolver: SecretResolver) -> list[dict[str, Any]]`. The response shape is unchanged (`voice_id`, `name`, `verified_languages`, …).
- `services/conversation/language.py`: `def fixed_language_instruction(language: str) -> str`; `LanguageTracker.__init__(self, default: str, supported: tuple[str, ...], *, unsupported_to_default: bool = False)`
- `services/config/agents.py`: `async def _validate_languages(conn, tenant_id, merged, *, lock_defaults: bool = False, requested: frozenset[str] = frozenset())`; `create_agent(..., language_mode: str | None = None)`
- `services/conversation/ai_provider_manager.py`: `class ModelNotReadyError(RuntimeError): def __init__(self, engine: str, model: str)`
- Agent API: `language_mode` is accepted on create and update and returned on reads.

## Risks
- Config and Conversation on different hosts or volumes would make `/local-models` report the wrong host. Mitigation: compose mounts the same `hf-cache` and feeds one `${OLLAMA_BASE_URL}` to Config (`OLLAMA_BASE_URL`) and Conversation (`VOICEAI_LLM_URL`, which `_make_ollama` now uses as its default `base_url`); an Ollama provider config with its own `extra.base_url` gets no status badge rather than a wrong "ready"; local `start_local.sh` shares `~/.cache/huggingface`; the docs state the colocation requirement; the runtime still falls back with one warning (criterion 34).
- Dedupe and the cap are per Config process, so several Config replicas on one host could each download. Mitigation: today's deployment runs a single uvicorn worker; HF file locks and Ollama's idempotent pull keep a duplicate correct, just wasteful. Documented.
- A download subprocess could outlive a Config restart. Mitigation: `aclose()` in lifespan terminates it and kills it after 5 s; no thread pool is created, so no non-daemon thread blocks exit (lesson 26).
- Abandoned selections fill disk (accepted in the PRD). Mitigation: only `LOCAL_MODELS` entries can be pulled (largest is Whisper `large-v3`), with at most 2 at once.
- Legacy agents with 3+ languages stay valid for unrelated edits and provider revalidation, because count rules run only when the request carries `supported_languages` or `language_mode`. Mitigation: the editor always sends `language_mode`, which routes its saves through the capped branch and forces the reduce prompt.
- The PRD's "tenant default language" does not exist in the schema; there is no such column on `tenants`. Mitigation: 0-language legacy agents prefill `"en"`, the registry's platform default, editable before save.
- The monolingual reply instruction changes LLM output. Mitigation: it is gated on the stored `language_mode == "monolingual"`, so legacy agents are unchanged until saved from the new editor (criterion 30).
- A saved agent whose Kokoro model or voice is not yet on disk (Save is allowed while downloading) would make `KPipeline` fetch it lazily at first synthesis, giving dead air or an unlogged offline failure. Mitigation: `_make_kokoro_tts` checks the three files with `local_files_only=True` and raises `ModelNotReadyError`, so the resolver logs once and falls back; the editor also triggers the pre-fetch on selection.
- macOS `say` does not exist in the Linux containers. Mitigation: status reads `unavailable` there, not `ready` (lesson 46).
- New log lines (resolver warning, Ollama 404) carry engine and model names only, never tenant or caller data (lesson 33).
- No new dependency or env var: `httpx`, `huggingface_hub` and `faster-whisper` are already in `requirements.txt`, and `OLLAMA_BASE_URL` already exists. `_MAX_CONCURRENT_DOWNLOADS` is a constant, not a knob.

## Test plan
Integration (Config, `services/config/tests/`, real DB as the existing suite uses):
1. Mode validation table, one test per row: multilingual with 3 languages → 400 naming "at most 2"; multilingual with 1 → 400 "second language"; monolingual with 0 or 2 → 400; `language_mode: "trilingual"` → 422; clearing a stored mode → 400. Monolingual save → `supported_languages IS NULL` and overrides cleared. Legacy row with 3 languages and NULL mode → an unrelated PATCH (name) still succeeds. A PATCH with 2 `supported_languages` and no mode stores `multilingual`; with 3 → 400 "at most 2". Multi→Mono with only `language_mode` sent → `language` kept, `supported_languages`, `tts_config_by_language` and `greeting_by_language` NULL. Template create → `language_mode = 'monolingual'`. Each fails if the mode branch is skipped.
2a. Revalidation (`test_agent_languages.py`): a monolingual Hindi agent whose STT row is edited to faster_whisper `small.en` → 400 naming the agent (fails if the WHERE is not widened); the same for a tenant default STT change; a moded multilingual agent survives an unrelated provider edit (fails with KeyError if the SELECT lacks `language_mode`).
2. Model-language support: monolingual Hindi with a faster_whisper `small.en` STT row → 400 naming `small.en` and Hindi. A monolingual English agent with a Kokoro `hf_alpha` base TTS → 400. This proves the `en` exemption was removed; it passes on old code only if the exemption remains.
3. `/local-models`, with `ModelDownloads` disk and Ollama checks monkeypatched: unknown `(engine, name)` → 400 and no job. A second trigger while running → no second job (assert the subprocess spawn count is 1). Two triggers of one missing model run with `asyncio.gather`, with the monkeypatched disk check yielding (`await asyncio.sleep(0)`) → spawn count 1. With 1 job running, two distinct missing models gathered → exactly one spawns, the other gets 429 (both fail if the post-await re-check is missing). A third distinct trigger with 2 running → 429, and the running jobs are untouched. A ready model → 200 and no spawn. Viewer → 403. A tenant-A admin and a tenant-B admin get identical `GET` bodies. That last check is a per-caller invariance argument (lesson 2): the route reads no tenant input; the test asserts that and that the body contains no tenant id.
4. `aclose()` terminates a live fake subprocess (a `sleep` stand-in) within the 5 s kill window.

Unit (Conversation):
5. `_refresh_node_prompt`: a monolingual-mode agent gets `fixed_language_instruction("hi")`; the same agent with `language_mode=None` gets no added line; a multilingual session still gets `reply_language_instruction(current)`. `LanguageTracker` with `unsupported_to_default=True`, switched to the secondary, then a confident third language → `current` is the primary; with the default `False` → stays secondary. The `search_knowledge` payload carries `answer_in` equal to the session language after a switch (criterion 26). `agent_resolver` with a factory raising `ModelNotReadyError` → returns None, and the log has exactly one warning naming the model (assert with `caplog` record count). `_make_kokoro_tts` with `hf_hub_download` monkeypatched to raise the HF not-found error for `voices/af_heart.pt` → `ModelNotReadyError("kokoro", "af_heart")` and `KokoroTTS` is never constructed; through `agent_resolver` the same case returns None with exactly one warning.

UI: `npm run lint && npm run build`, and the `grep -rn "supported_languages" admin-ui scripts docs` sweep shows no remaining default-plus-secondary toggling (criterion 33).
