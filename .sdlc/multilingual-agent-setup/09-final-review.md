1. [blocking] A Kokoro voice that isn't on disk is now fetched inside `load()` on the call-setup path, and a failed fetch drops the call — `services/conversation/providers/tts/kokoro.py:152-158,173` via `ai_provider_manager.py:207-209` — fails when: the base weights are on disk and a tenant's row names a registry voice not yet fetched (new voice picked in LocalVoicePicker, or an HF_HUB_OFFLINE / no-egress host). `_make_kokoro_tts` → `tts.load()` → `_fetch_files` → the subprocess exits 1 → `RuntimeError`, not `ModelNotReadyError`. Nothing in `provider_bundle._get_or_default` (:133-144) catches it, so the bundle fails and the routed call is rejected (lesson 49). At HEAD, `load()` built only the base pipeline and KPipeline fetched the voice lazily on first synthesis. Even on success, call setup now waits for a subprocess and a free slot: with two multi-GB Whisper downloads running, a 0.5 MB voice queues behind them for minutes. — fix: don't fetch the voice in the ready-weights `load()` (leave it lazy as before), or catch the fetch failure there and fall through to the lazy path.
2. [minor] Downloads are keyed on the registry name, not on what is fetched, so aliases run the same multi-GB download twice and hold both slots — `services/conversation/providers/stt/faster_whisper.py:110` — fails when: one row uses `large` and another `large-v3` (or `turbo` and `large-v3-turbo`), both not on disk. Two subprocesses fetch the same repo and take both MAX_CONCURRENT_DOWNLOADS slots, so Kokoro's base weights and every other model wait behind them. — fix: key on the resolved repo (`faster_whisper.utils._MODELS.get(name, name)`).
3. [minor] A failed Kokoro download has no back-off: the deferred instance starts a new subprocess on every synthesis — `services/conversation/providers/tts/kokoro.py:193` — fails when: HF is unreachable. Each sentence on a call holds the instance lock for a Python start-up plus a network timeout before failing. Whisper backs off per instance with `_RETRY_AFTER_S`. The retry count matches HEAD, where KPipeline retried per sentence; the subprocess cost is new. — fix: record `_last_failure` in `_fetch_files` and skip the fetch inside the same `_RETRY_AFTER_S` window.
