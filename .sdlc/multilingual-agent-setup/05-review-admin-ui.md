# Code review
VERDICT: AMBER

1. [blocking] Legacy region-tagged languages are not normalised to base codes — `admin-ui/lib/agentDraft.ts:30` — fails when: a stored agent (or an old draft) has `language: "en-US"` (an old `LANGUAGES` option, also set by macOS voice picks). It loads as `languages: ["en-US"]`, which matches no `SUPPORTED_LANGUAGES` option. The mono select shows English while the state holds "en-US". `supports(engine, name, "en-US")` is false for every catalogue model, so the free voice list is empty and the STT warning says "can't recognise en-US". The first language edit also sends "en-US" with a mode — fix: map each code through `baseLanguage()` in `deriveLanguageDraft`, dropping duplicates.
2. [blocking] The edit page blocks every save on legacy multilingual agents with no per-language voice — `admin-ui/app/(console)/agents/[tenantSlug]/[agentSlug]/page.tsx:196` — fails when: a legacy agent has `supported_languages: ["en","hi"]`, a multilingual ElevenLabs base voice and `tts_config_by_language: null`, which the server accepted. `canSave` is false, so renaming it or editing its prompt never autosaves or saves, and no reason is shown. This breaks the design rule that an unrelated edit to a legacy row must succeed — fix: apply the voice check only when the language payload changes, or show the blocking reason.
3. [blocking] Per-language greetings can no longer be edited, but they are still spoken — `admin-ui/app/(console)/agents/[tenantSlug]/[agentSlug]/page.tsx:218` — fails when: a multilingual agent has `greeting_by_language: {en: "Hi"}`. The user edits the Greeting field to "Hello", but `pipeline.py:552` still plays "Hi", because the localized entry replaces the opening line. `keptGreetings` even carries it forward. The design did not ask for the greeting editor to be removed — fix: restore the default language's greeting editor, or clear or merge `greeting_by_language[primary]` when `greeting` is saved.
4. [minor] Changing a monolingual agent's language silently unassigns its voice — `admin-ui/components/AgentVoiceSettings.tsx:262` — fails when: a monolingual agent with a multilingual ElevenLabs voice switches from English to Hindi. `changeLanguages` calls `onAssign("tts", ttsByLanguage["hi"] || null)`, so `tts_config_id` is saved as null and the agent falls back to the workspace default voice — fix: only hand over `ttsId` in multilingual mode, or keep it when the current voice supports the new language.
5. [minor] `ttsLanguages` has no callers, and premium voices are filtered by `verified_languages` alone, against the design — `admin-ui/lib/engineCatalog.ts:188` — fails when: an ElevenLabs account on `eleven_turbo_v2` (English-only) lists a voice that is verified for Hindi. That voice is offered for Hindi, and the server rejects the save — fix: intersect with `ttsLanguages(account)` at `AgentVoiceSettings.tsx:128`, as the design says, or delete the dead function.
