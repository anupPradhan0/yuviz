VERDICT: GREEN

Both open items from the previous round are closed: the [medium] unbounded download subprocesses and the [low] ollama `/api/tags` decompression residual. No new findings.

## Findings
None open.

## Verified controls
- Downloads are deduped by what they fetch, process-wide. `services/conversation/model_downloads.py` keeps a module-level `_in_flight[(engine, name)]`. Whisper calls `fetch(("faster_whisper", self._model_size), …)` (`providers/stt/faster_whisper.py:110`) and Kokoro calls `fetch(("kokoro", "base"|<registry voice>), …)` (`providers/tts/kokoro.py:160`). device, compute_type, language, speed and lang_code are not part of either key, so the many instances that `_not_ready_whisper` / `_not_ready_kokoro` build per tenant-chosen setting all share one subprocess per file set.
- Every possible key comes from a registry. Whisper reaches `load_when_needed()` only when `find_local_model("faster_whisper", model_size)` matches (`ai_provider_manager.py:139`). A Kokoro voice key is added only for a registry voice, and the base key is a constant. A tenant therefore cannot mint new keys, and in-flight subprocesses are capped at `min(2, number of registry keys)`.
- There is a per-process concurrency cap. `_slots = asyncio.Semaphore(2)` is acquired around `create_subprocess_exec`, so callers past the cap wait as coroutines and no process is spawned for them. Test `test_concurrent_downloads_are_capped_and_the_rest_wait` covers this.
- A successful download is never repeated. `_done` is set only on exit 0, and `fetch` returns early for a key in `_done`. When `WhisperModel` fails after a good download (for example on a host with no CUDA), `_load_allowing_download` retries `download` and then `load` only every `_RETRY_AFTER_S`, and the download step is a no-op. Only the cheap local load is retried. A failed download is not added to `_done`, so a later caller can try again, still at most one process per key.
- A tenant cannot hold download slots indefinitely. The only contents a slot can fetch are registry models from fixed upstream repos, each at most once successfully per process. A tenant can make the host fetch the registry, which is the intended allowlist, but cannot pin a slot with a slow or attacker-controlled source. A caller's cancellation is shielded (`asyncio.shield`), so one call hanging up does not kill another tenant's download. `stop_downloads()` is reached only from `close_not_ready_providers()` at shutdown (`__main__.py:534`).
- Provider-config writes validate whisper `device` ∈ {cpu, cuda, auto} and `compute_type` ∈ ctranslate2's fixed set (`services/config/provider_configs.py` `require_supported_whisper`) on create and on update. Unhashable values raise rather than pass. Only changed values are checked, so an `extra` stored under another engine is grandfathered on an engine switch. That has no download impact now that downloads are keyed on the model alone. Test `test_a_bogus_whisper_device_or_compute_type_is_a_400_on_write` covers the write check.
- Subprocesses are argv-only with no shell. The script is a constant. Whisper's only argument is the registry name. Kokoro's arguments are the constant `KOKORO_REPO` and constant or registry-voice filenames. A process is killed if its task is cancelled.
- Every new registry name (`large-v1`, `large-v2`, `large`, `large-v3-turbo`, `turbo`, `distil-large-v2`, `distil-large-v3`, `distil-large-v3.5`, `distil-medium.en`, `distil-small.en`) is a key in the installed faster-whisper 1.2.1 `utils._MODELS`. Each maps to a fixed upstream repo: Systran/*, `mobiuslabsgmbh/faster-whisper-large-v3-turbo`, or `distil-whisper/distil-large-v3.5-ct2`. None contains `/`, so `download_model` never treats one as an arbitrary repo id. A name missing from `_MODELS` in another version raises ValueError and fetches nothing.
- The Ollama `/api/tags` call sends `Accept-Encoding: identity` and returns early unless `Content-Encoding` is absent or exactly `identity`. Combined values such as `gzip, identity` and empty values are refused. Bytes are therefore never decompressed, and the 1 MB cap bounds memory at about 1 MB plus one network read. The call still uses `guarded_client` and logs fixed codes only.
- Targeted tests pass: 88 in `test_model_downloads`, `test_ai_provider_manager` and `test_ollama_llm`, plus 5 whisper validation cases in `test_provider_url_guard`. No test directly asserts that two instances with different `compute_type` share one subprocess or that a failed load after a good download skips the download. Both properties follow from the code paths traced above and from the module-level dedupe and `_done` tests.
