[blocking] Adding `FasterWhisperSTT.aclose()` makes the existing "not-ready Ollama client" cleanup cancel the shared Whisper background download on every fallback — `services/conversation/provider_bundle.py:138-139` (with `providers/stt/faster_whisper.py:120`) — fails when: an agent's faster_whisper model is not on disk and the process default STT serves it (the normal case). `_make_faster_whisper` calls `load_when_needed()` and raises ModelNotReadyError(provider=inst), then `_get_or_default` sees `aclose` and awaits it. That cancels `_load_task` before it starts (or kills the subprocess mid-download). The instance stays in `_not_ready_whisper`, and every later resolution, including prewarm, repeats the start-then-cancel. Cancellation does not set `_last_failure`. Result: the model never downloads, and the agent stays on the default STT for the life of the process. A scratch repro confirms it: after load_when_needed() + aclose(), the download never started and the task was cancelled. — fix: name the whisper method something the bundle does not duck-type (e.g. `stop_download()`), call that from `close_not_ready_providers`, and leave the bundle's `aclose` cleanup to Ollama only.
