# Design: Guard the [[END_CALL]] marker against mid-conversation hangups

## Approach
`_llm_to_tts` already owns the turn's `directives` list (filled in place) and is the only place that knows the full spoken reply. So the guard runs there once, after the stream ends and `stream_buf.flush()` runs, before the final `end_call = any(...)` line (`pipeline.py:1378`). It runs only if an `EndCallDirective` is in `directives` and the turn was not cancelled. On rejection it removes the `EndCallDirective` from `directives` in place and logs `end_call_rejected`. The turn handler then takes `end_call` from `directives` after the loop, not from the last yielded `marker_seen`. The `end_call=True` values yielded mid-stream before the guard runs are therefore never acted on (AC12). A marker-only rejected reply then has `not directives`, so it falls through to the existing never-go-silent branch, which speaks `end_call_check` rather than `silent_turn_text` when the marker was rejected. The decision itself is a pure sync module-level function next to `_build_end_call_instruction`, matching the existing `_claims_booking_without_tool_call` pattern. The phrase lists live in the i18n modules beside `STRINGS`. A regex/keyword list inside `pipeline.py` was rejected because AC6 requires per-language tables with an English fallback.

Decision order (first match wins), evaluated on the reply's directive-free text:
1. The last sentence of the reply ends in a question mark (`?`, `？`, `؟`): reject, `reason=question`. The last sentence is the reply split by the existing `_SENTENCE_RE`, keeping the last non-empty piece, with trailing whitespace and quotes stripped. Runs first in every mode and for every language.
2. Scripted mode (`self._farewell_message is not None`): the system speaks the farewell, so step 1 is the only check; accept otherwise (AC3, a marker-only reply included). The call site in `_llm_to_tts` does this inline and does not call `_end_call_rejection`.
3. The language is unknown (`None`, e.g. "multi") or has no phrase table (`has_phrase_tables(language)` is false: es, fr, de, pt, it, ja, zh, ...): accept. English phrases cannot match a native goodbye, and `_phrase_tokens` splits on whitespace so it cannot segment ja/zh at all; rejecting would stop those agents from ever ending a call. `test_every_registered_language_has_a_phrase_table_or_fails_open` forces a choice whenever a language is added to `LANGUAGES`.
4. The caller's last sentence (`_last_sentence(caller_text)`, not the whole utterance) contains a closure phrase from the union of the spoken-language table and the English table: accept.
5. The last sentence contains a farewell phrase from the same union: accept.
6. Otherwise reject: `reason=marker_only` if the reply is empty, else `reason=no_closure`.

Language input: a session language if the agent is multilingual, else `_guard_language` set in `_init_languages` from `agents.language`, then the STT row's, then the TTS row's language (the `resolve_languages` order), `"en"` when none is set. A marker-only rejection on a main turn (`silent_turn_text == "fallback_llm_error"`) speaks the `end_call_check` string ("Is there anything else I can help you with?", en and hi) instead of the caller-facing error text, via a local `end_call_rejected` flag in `_llm_to_tts`; the transfer-failed recovery keeps its own `transfer_failed_fallback`. A legacy free-text `agents.language` ("English") that normalizes to nothing falls through to the next set source, and `"en"` when none; only an explicit `"multi"` yields `None`.

The English tables also accept a thanking caller ("thanks", "thank you", "okay thanks") and the farewells "have a wonderful day", "have a lovely day", "talk to you soon", "see you"; `hi` accepts "धन्यवाद" and "शुक्रिया" from the caller. The question veto still runs first.

Deviation from the PRD: AC1 lists `।` as a question terminator. `।` is the Hindi full stop, and `hi.STRINGS["fallback_goodbye"]` itself ends in it. Treating it as a question would veto every Hindi farewell and break AC5. `।` is therefore not a question terminator. Hindi questions in our tables already end in `?` (`hi.STRINGS["fallback_llm_error"]`).

Phrase matching is token-sequence containment, not `\b` regex. Python's `\b` breaks inside Devanagari words because matras such as `ा` are not `\w`. Both the text and the phrase are casefolded, `’` is mapped to `'`, the text is split on whitespace and punctuation (`.,!?;:…।॥؟？` and quotes), the tokens are rejoined with single spaces and padded with a space at each end, and the match is ` phrase ` in ` text `.

## Interfaces
- `i18n.closure_phrases(language: str | None) -> tuple[str, ...]`
- `i18n.farewell_phrases(language: str | None) -> tuple[str, ...]`
- `pipeline._phrase_tokens(text: str) -> str`: normalized, space-padded token string.
- `pipeline._end_call_rejection(reply_text: str, caller_text: str, language: str | None) -> str | None`: returns `None` to accept, or a reason token (`question`, `no_closure` or `marker_only`). It does no I/O and has no await.
- `PipelineConversationHandler._llm_to_tts(..., silent_turn_text: str = "fallback_llm_error", caller_text: str = "")`: the yielded tuple is unchanged.
- The exact guard call in `_llm_to_tts`, the single site that must satisfy it (lesson 32): `_end_call_rejection(reply_text, caller_text, self._session_language(session_id) or self._guard_language)`, reached only for an unscripted agent. A scripted agent (`self._farewell_message is not None`) never calls the function: the site rejects with `question` only when the last sentence ends in a question mark and `reply_text` is non-empty, and otherwise accepts.
- Guard input and scripted short-circuit (as built): the guard's `reply_text` argument is `transition_text + reply_text`, so transition speech the caller heard counts toward closure and the question veto. For a scripted agent (`self._farewell_message is not None`) a marker-only reply skips the guard entirely, whatever the transition said, because the fallback speaks the scripted farewell. `_PHRASE_SPLIT_RE` also splits on em-dash, en-dash and parentheses, so unspaced "All set—goodbye!" and "Done (goodbye)" tokenise.
- Prompt change (as built): the unscripted end-call instruction now reads "after your spoken words, which must include a brief goodbye", pinned by `test_no_scripted_messages_keeps_spoken_word_instructions`.
- The exact call at `on_speech_ended:808`: `self._llm_to_tts(messages_for_llm, cancel_event, session_id, directives, tool_calls_made, store=history, caller_text=stt_result.text)`.

## Risks
- A consumer acts on a mid-stream `end_call=True` before the guard runs (AC12): `grep -rn "_llm_to_tts" services libs scripts` lists exactly two call sites (`pipeline.py:808`, `:1056`). 1056 discards the flag, and 808 now reads `directives` after the loop. Nothing yields `HandlerResponse(end_call=True)` inside the loop. Workflow turns, the web test and routed calls all go through `on_speech_ended`, so this one post-loop line recovers on every path (lesson 49).
- Deriving `end_call` from `directives` could lose the latch the comment at `pipeline.py:1298` protects: `directives` is append-only except for the guard's removal, so transition speech or a filler still cannot clear it. `test_an_end_call_marker_survives_a_transition_in_the_same_turn` (with its AC19 text) proves this.
- `।` is not treated as a question terminator, which deviates from PRD AC1: as the PRD wrote it, every Hindi farewell would be vetoed and AC5 broken. A unit test asserts that `hi` `fallback_goodbye` plus the marker is accepted.
- Closure phrases match anywhere in the caller's last sentence, so "don't say bye yet" counts as a closure: the guard only narrows today's behaviour (every marker hung up). A false accept is no worse than today. Phrases are multi-word wherever a single word is ambiguous ("no" alone is never listed).
- A guard rejection on the transfer-failed path (1056, `caller_text=""`) logs `end_call_rejected` for a flag that path already ignores: the log is accurate (that marker was not honoured), so it is left as is rather than adding a parameter just to suppress it.
- The log line could leak transcript text (lesson 33): the format string carries only `reason` (a fixed token) and `session_id`. The AC8 test asserts that neither the caller nor the reply text appears in `caplog.text`.
- A non-English session gets an English farewell false-accept (the reply "bye" in a `hi` session): this is intended by the PRD's union rule. It is accept-side only and matches today's behaviour.
- `CLOSURE_PHRASES` and `FAREWELL_PHRASES` are new optional i18n attributes: the PRD forces per-language tables (AC6). They follow the existing `TOOL_FILLERS` contract, with no new loader.

## Test plan
Unit (`test_end_call_guard.py`, deployed tables, no monkeypatched constants (lesson 25)). Each row asserts the exact return value:
1. A question veto overrides a closure: caller "goodbye", reply "Anything else?" gives `question`. Repeat for `？` and `؟`. Reply "Anything else? Bye." gives `None`.
2. AC4 pair: caller "I want to book", reply "Your booking is confirmed. Goodbye." gives `None`. The same caller with reply "Your booking is confirmed." gives `no_closure`.
3. Language: `hi`, caller "बस इतना ही" with an empty reply gives `None` (AC5). `hi`, caller "that's all", reply "All set." gives `None`. `hi`, caller "tell me more", reply "All set." gives `no_closure` (AC18). Language `"fr"` (no table), caller "tell me more", reply "All set." gives `None` (fails open, no phrase table), while a trailing question in `fr` still gives `question` (AC7). `hi` reply `t("fallback_goodbye","hi")` with a non-closing caller gives `None` (the `।` decision). `hi`, caller "नमस्ते, मुझे बुकिंग करनी है", reply "आपकी बुकिंग हो गई।" gives `no_closure` (a greeting is not a closure).
4. Scripted mode is handled inline in `_llm_to_tts`, not in `_end_call_rejection`, so it is tested at handler level in `test_pipeline.py` (a scripted farewell ends the call without a closing caller; a trailing question still vetoes). Unit level: an unscripted empty reply with a non-closing caller gives `marker_only`.

Integration (`test_pipeline.py`, through `on_speech_ended`):
1. AC16 (the rewritten 582-605 test): the result has no `end_call=True`, `t("end_call_check","en")` was passed to `tts.synthesize` and neither `_FALLBACK_GOODBYE` nor `fallback_llm_error` was, no `[[END_CALL]]` appears in history, and exactly one `end_call_rejected reason=marker_only session=` record is logged. AC17 is its counterpart: caller "goodbye" gives fallback goodbye audio before `end_call=True` and no rejection log (AC9).
2. AC1 at handler level: the reply "Can I help with anything else? [[END_CALL]]" is spoken, no `end_call`, and the history holds the question without the marker (AC10). The AC8 assertion is that caplog contains neither transcript string.
3. AC11: monkeypatch `pipeline._end_call_rejection` with a spy and run a no-marker turn. The spy is never called. It fails if the guard runs unconditionally.
4. AC14: the `_FakeToolOrchestrator` `ToolTokenEvent` with a question plus the marker is rejected. The existing tests at 669, 2208, 2582 and 2606 pass unmodified (AC13, AC15).
